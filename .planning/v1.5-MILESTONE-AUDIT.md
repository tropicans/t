## Cross-Phase Integration & E2E Verification

### Wiring Mapping

- **Phase 13 → Phase 14 (Data Engine & Schema to Public Route & Auth Bridge)**:
  - `src/lib/invitations.ts` (`getInvitationByToken`, `validateInvitationStatus`) is directly imported and evaluated by the server component `src/app/invite/[token]/page.tsx` to display invitation state and inviter metadata.
  - `src/app/invite/[token]/actions.ts` stores the verified token in an HTTP-only secure cookie `taut_invite_token` before redirecting to Google OAuth.
  - `src/lib/auth.ts` (`authorizeUserSignIn`) checks `prisma.user`, `ALLOWED_EMAILS`, and reads the invitation cookie using `claimInvitationTransaction` to dynamically provision new users and update invitation quotas atomically.
- **Phase 13 → Phase 15 (Validation Helpers to Dashboard Server Actions & Queries)**:
  - `src/lib/invitations.ts` (`createInvitation`, `revokeInvitation`, `getUserInvitations`) powers the backend logic in `src/app/actions/invitations.ts`.
  - `src/app/dashboard/invitations/page.tsx` fetches invitation records with user affiliations for display and status computation.
- **Phase 14 → Phase 15 (Public Links to Dashboard Administration)**:
  - Links generated and copied from `src/app/dashboard/invitations/invitation-form.tsx` and `invitation-list.tsx` point directly to `/invite/[token]`.
  - New users dynamically onboarded via the public landing page in Phase 14 are immediately reflected in the Phase 15 claimed users accordion in `/dashboard/invitations`.

### E2E Flows Verified

1. **Invitation Generation Flow**:
   - Authenticated user navigates to `/dashboard/invitations`.
   - Selects "Tautan Terbuka" (with quota and expiry) or "Khusus Email".
   - Clicks "Buat Link Undangan".
   - Modal/result card provides full URL with one-click copy button and instant visual toast confirmation.
2. **Public Acceptance & Onboarding Flow**:
   - Invitee clicks `https://<domain>/invite/<token>`.
   - Server validates token status (active, quota remaining, not expired, matching email restriction).
   - Card presents inviter name and invite parameters.
   - Invitee clicks "Masuk dengan Google".
   - NextAuth callback provisions new user record in PostgreSQL, increments usage count, marks as `ACCEPTED` if quota reached, and redirects user to `/dashboard`.
3. **Existing User Direct Access Flow**:
   - Existing user logs in via `/login` without invite token.
   - NextAuth Tier 1 check matches database record in `prisma.user` and grants immediate access to `/dashboard`.
4. **Revocation & Route Protection Flow**:
   - Admin clicks "Cabut" on an active invitation and confirms prompt.
   - Invitation transitions to `REVOKED` in database.
   - Subsequent attempts to load `/invite/[token]` render the editorial invalid/revoked state card.
   - Reserved route check ensures no short link or microsite slug can claim `/invite`.
