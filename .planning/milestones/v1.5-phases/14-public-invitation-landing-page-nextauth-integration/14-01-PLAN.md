# Plan 14-01: Public Invitation Landing Page & NextAuth Integration

## Objective
Build the public invitation landing page at `/invite/[token]` with Claude editorial styling to validate and display invitation status, and integrate NextAuth's `signIn` callback to permit dynamic user onboarding via valid invitation tokens while keeping existing database users and `ALLOWED_EMAILS` bootstrap access fully operational.

## Proposed Changes

### 1. NextAuth Callback Bridge (`AUTH-01`, `AUTH-02`)
- **File:** `src/lib/auth.ts`
- Update `authOptions.callbacks.signIn`:
  1. **Existing Registered Users (`AUTH-02`)**: Query `prisma.user.findUnique({ where: { email: userEmail } })`. If found, allow sign-in immediately (`return true`) and update name/image if provided. Any previously onboarded user can sign in without needing an invitation token again.
  2. **Bootstrap Allowlist (`AUTH-02`)**: Check `ALLOWED_EMAILS` environment variable. If present and email matches, allow sign-in and upsert `prisma.user`.
  3. **Invitation Token Claim (`AUTH-01`)**: Read `taut_invite_token` cookie from request headers via `cookies()`. If present:
     - Query invitation using `getInvitationByToken(token)`.
     - Validate status using `validateInvitationStatus(invitation, userEmail)`.
     - If valid: atomically execute transaction creating `User` record (with `invitationId: invitation.id`), increment `invitation.usesCount`, update `invitation.status` to `ACCEPTED` if quota exhausted, delete `taut_invite_token` cookie, and allow sign-in (`return true`).
     - If invalid: log unauthorized attempt and deny sign-in (`return false`).
  4. **Unauthorized Fallback**: If user is not in DB, not in `ALLOWED_EMAILS`, and has no valid invitation, deny sign-in (`return false`).

### 2. Cookie Server Action (`AUTH-01`)
- **File:** `src/app/invite/[token]/actions.ts` [NEW]
- Provide `setInvitationCookie(token: string)` server action that sets `taut_invite_token` in `cookies()` with `path: "/"`, `httpOnly: true`, `sameSite: "lax"`, `maxAge: 3600`.
- Provide `clearInvitationCookie()` helper.

### 3. Invitation Action Client Component (`INV-03`)
- **File:** `src/app/invite/[token]/invite-action.tsx` [NEW]
- Client Component featuring:
  - "Masuk dengan Google" primary button styled with Claude warm terracotta (`bg-primary text-primary-foreground hover:bg-terracotta-active rounded-full font-medium h-12 w-full`).
  - Google 'G' multicolored SVG icon.
  - On click, calls `setInvitationCookie(token)` and initiates `signIn("google", { callbackUrl: "/dashboard" })`.
  - Loading state during sign-in trigger.

### 4. Public Invitation Landing Page (`INV-03`)
- **File:** `src/app/invite/[token]/page.tsx` [NEW]
- Server Component resolving `params: Promise<{ token: string }>`.
- Query `getInvitationByToken(token)` and validate via `validateInvitationStatus(invitation)`.
- Apply Claude editorial design system:
  - Canvas floor (`bg-background text-foreground`).
  - Centered `BrandLogo` header.
  - **Valid Invitation State**:
    - Editorial card (`bg-card border border-border shadow-2xl rounded-3xl p-8 max-w-md w-full`).
    - Badge: "Undangan Terverifikasi" in subtle warm terracotta tint.
    - Headline: `font-heading text-3xl font-bold tracking-tight text-foreground` ("Bergabung dengan Taut").
    - Inviter Info: Inviter avatar / initials + *"**{inviterName}** mengundang Anda untuk bergabung ke Taut."*
    - Details pill / metadata:
      - Quota display (e.g., "Sisa kuota: X undangan" for multi-use tokens).
      - Expiration notice if `expiresAt` set (formatted with date-fns).
      - Email restriction hint if target email is designated.
    - `InviteAction` button to initiate Google OAuth.
  - **Invalid Invitation State**:
    - Editorial card with warning/error banner.
    - Clear explanatory message (e.g. "Tautan Telah Kedaluwarsa", "Kuota Habis", "Tautan Telah Dicabut").
    - Button to navigate back to `/login`.

### 5. Automated Unit Testing (`TEST-01`)
- **File:** `src/lib/auth.test.ts` [NEW]
- Vitest unit tests verifying:
  - Existing user in DB allows login and updates profile without invite token.
  - Email in `ALLOWED_EMAILS` allows login and creates user without invite token.
  - User with valid open invite token allows login, creates DB user, increments usage, and links invitation.
  - User with valid email-restricted invite token allows login when Google email matches.
  - User with valid email-restricted invite token is rejected when Google email mismatches.
  - Expired, exhausted, or revoked invitation token is rejected.
  - Unauthorized user without invitation or allowlist is denied.
