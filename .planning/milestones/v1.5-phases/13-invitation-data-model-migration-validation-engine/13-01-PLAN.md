# Plan 13-01: Invitation Data Model, Migration & Validation Engine

## Objective
Establish the foundational data layer and backend validation engine for the invitation system. Define the `Invitation` Prisma model, run database migrations, register `"invite"` as a protected system route in `RESERVED_SLUGS`, provide comprehensive token generation and validation helpers, and verify everything with an automated Vitest unit test suite.

## Proposed Changes

### 1. Database Schema & Migration (`INV-01`)
- **File:** `prisma/schema.prisma`
- Add `Invitation` model:
  - `id`: String (cuid)
  - `token`: String (unique, indexed)
  - `email`: String? (optional target email, indexed)
  - `invitedById`: String
  - `invitedBy`: User relation (`"CreatedInvitations"`)
  - `maxUses`: Int (default 1)
  - `usesCount`: Int (default 0)
  - `expiresAt`: DateTime? (optional expiration)
  - `status`: String (default `"PENDING"`, indexed; values: `PENDING`, `ACCEPTED`, `EXPIRED`, `REVOKED`)
  - `createdAt`: DateTime (default now)
  - `updatedAt`: DateTime (updatedAt)
  - `claimedUsers`: User[] relation (`"ClaimedInvitation"`)
- Update `User` model:
  - `createdInvitations`: Invitation[] relation (`"CreatedInvitations"`)
  - `invitationId`: String?
  - `invitation`: Invitation? relation (`"ClaimedInvitation"`)
- Generate Prisma Client and create migration SQL.

### 2. Route Collision Protection (`INV-02`)
- **File:** `src/lib/validators.ts`
- Add `"invite"` to `RESERVED_SLUGS` to ensure public short codes and microsite slugs cannot hijack the `/invite/[token]` URL namespace.

### 3. Invitation Validation Engine (`INV-01`, `INV-02`)
- **File:** `src/lib/invitations.ts`
- Functions:
  - `generateInvitationToken()`: Generates a URL-safe, high-entropy random token.
  - `validateInvitationStatus(invitation, targetEmail?)`: Pure validator returning `{ valid: boolean, reason?: string }` considering expiration (`expiresAt`), exhaustion (`usesCount >= maxUses`), revoked status, and email match.
  - `createInvitation(input)`: Prisma helper to create an invitation.
  - `getInvitationByToken(token)`: Query invitation by unique token with inviter metadata.
  - `claimInvitationTransaction(token, userId, userEmail)`: Atomic claim helper that updates usage counters, marks status as `ACCEPTED` when quota is exhausted, and associates user.
  - `revokeInvitation(invitationId, userId)`: Safe revoking helper.

### 4. Automated Testing (`TEST-01`)
- **File:** `src/lib/invitations.test.ts`
- Tests:
  - Token generation format & randomness
  - Status validation for active, expired, exhausted, and revoked tokens
  - Specific email validation vs open invitation validation
  - Collision check verifying `invite` is blocked in `validateSlugCollision`
  - All tests passing with 0 TypeScript compilation errors
