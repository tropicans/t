# Milestone v1.6: Role-Based Access Control (RBAC) & Audit Activity Trail

**Status:** ✅ SHIPPED 2026-09-16
**Phases:** 16-18
**Total Plans:** 3

## Overview

Implement complete Role-Based Access Control (RBAC) across three distinct tiers (`ADMIN`, `OPERATOR`, `MEMBER`), complemented by a non-blocking system-wide activity audit trail engine (`AuditLog`) and an intuitive management timeline in the administrator dashboard.

## Phases

### Phase 16: RBAC & Audit Data Model, Migration & Auth Synchronization
- [x] 16-01: Prisma schema enum `Role`, model `AuditLog`, migration, dan sinkronisasi role saat login Google OAuth (NextAuth JWT session) — completed 2026-09-16

**Goal:** Menambahkan enum `Role` dan model `AuditLog` di Prisma schema, memperbarui Prisma client, memperluas tipe NextAuth session dengan claims role, dan menyelaraskan sinkronisasi role saat user login dengan Google OAuth (`ALLOWED_EMAILS` -> `ADMIN`, `GLOBAL_DASHBOARD_VIEWER_EMAIL` -> `OPERATOR`).
**Requirements:** RBAC-01, RBAC-02, RBAC-03, AUDIT-01, TEST-01
**Success Criteria:**
1. Enum `Role` (`ADMIN`, `OPERATOR`, `MEMBER`) dan model `AuditLog` terdefinisi di `prisma/schema.prisma`.
2. NextAuth session token memuat `role`, `isAdmin`, dan `isOperator`.
3. Unit tests memvalidasi resolusi role dan session mapping.

### Phase 17: Activity Audit Logger Engine & Mutations Instrumentation
- [x] 17-01: Engine pencatatan log audit `logAuditEvent()` dan instrumentasi pada server actions (ShortLink, Microsite, Invitation, User role) — completed 2026-09-16

**Goal:** Membuat helper server-side `logAuditEvent()` di `src/lib/audit.ts` yang fail-safe dan menginstrumentasikannya pada seluruh server actions mutasi (Short Links, Microsites, Invitations) agar setiap tindakan "siapa melakukan apa" tercatat di database.
**Requirements:** RBAC-03, AUDIT-02, AUDIT-03, TEST-01
**Success Criteria:**
1. Helper `logAuditEvent` menyimpan record aktivitas secara non-blocking.
2. Aksi CRUD Short Links, Microsites, dan Invitations memanggil `logAuditEvent`.
3. Operator dibatasi hanya baca dan dilarang memodifikasi/menghapus resource pengguna lain.

### Phase 18: Dashboard UI Role Management & Audit Trail Timeline
- [x] 18-01: Antarmuka pemilihan role user di tab Users, tampilan linimasa Audit Trail khusus Admin, dan verifikasi menyeluruh — completed 2026-09-16

**Goal:** Menyediakan kontrol visual bagi Admin untuk mengubah role pengguna lain via dropdown selector dengan proteksi self-lockout, serta menambahkan tab Audit Trail untuk memantau linimasa aktivitas mutasi sistem.
**Requirements:** UI-01, UI-02, TEST-01
**Success Criteria:**
1. Admin dapat mengubah role user lain menjadi ADMIN, OPERATOR, atau MEMBER.
2. Admin dicegah mendemosi dirinya sendiri untuk menghindari self-lockout.
3. Linimasa Audit Trail menampilkan aktivitas mutasi dengan timestamp, pelaku, dan rincian metadata.
4. Seluruh unit tests (97 tests) lulus dan build production sukses.

## Milestone Summary

**Key Decisions:**
- Decision: Database-backed `Role` enum (`ADMIN`, `OPERATOR`, `MEMBER`) with bootstrap sync during Google OAuth sign-in.
- Decision: Operator role is strictly read-only; cannot edit/delete others' resources or access audit logs.
- Decision: Self-lockout prevention on role management preventing admins from demoting their own active account.
- Decision: Non-blocking audit logger with null-safe error handling to guarantee zero business mutation interruption.
- Decision: Integrated Audit Trail tab directly into `/dashboard/invitations` for centralized administration.

**Issues Resolved:**
- Established 3 clear permission tiers: Admin (full access), Operator (global read-only dashboard viewer), Member (own resources only).
- Recorded full accountability trail ("siapa melakukan apa") for all system mutations.
